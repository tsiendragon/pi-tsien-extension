# Memory：从失败中形成可复用经验的技术设计

日期：2026-10-21
状态：已按本设计实现第一版（经双重复核后收紧自动采纳）

## 1. 目标

让助手从真实工作过程中积累长期有用的记忆，尤其是“出错后如何修好”的经验，同时避免：

- 把一次性输入、临时报错或未经证实的猜测写成长期记忆；
- 每条用户输入都调用模型，增加费用和干扰；
- 把“被检索到”误当成“已使用”或“有效”。

新记忆默认使用简体中文、一句话、最多 120 字，并保留任务编号、路径、版本号、数字和产品名。

## 2. 非目标

第一版不做：

- 每次用户输入都调用轻量模型并立即写库；
- 保存完整错误日志、堆栈、源码或凭证；
- 没有修复和验证就生成“成功经验”；
- 自动把记忆发布成技能、规则或知识；
- 声称记忆已经提升任务成功率。

## 3. 当前链路

```text
用户输入
  → 规则识别明确的记住 / 更正 / 遗忘
  → 主 Agent 正常工作
  → 记录工具结果
  → 本轮结束
  → 规则捕获 + 模型提炼
  → 自动分流：生效 / 待确认
  → 后续提问时检索
  → 上下文预算裁剪
  → 记录真正入模的记忆
```

现有问题：只收集成功工具名称，失败工具没有进入提炼流程，因此无法形成失败修复经验。

## 4. 核心设计

### 4.1 输入预筛，不直接写库

明确的用户意图继续由规则同步处理。以后若增加轻量模型输入预判，它只负责标记“本轮可能值得提炼”，不得在输入时直接形成长期记忆。

最终写入必须等本轮结束，因为长期价值通常取决于后续工具结果和回答，而不是用户的一句话。

### 4.2 恢复证据：同一工具先失败、后成功

运行时按顺序记录本轮工具结果，并以增量状态保存，避免长轮次截断丢失未恢复失败。只有同一工具出现：

```text
失败 → 后续成功
```

才把它列为“已恢复工具”。

以下情况不算恢复证据：

- 只有失败；
- 先成功后失败；
- 工具 A 失败、无关的工具 B 成功；
- 网络超时、用户取消、权限拒绝等一次性失败，且没有修复过程。

“同一工具恢复”只是形成经验的线索，不证明模型对根因的总结正确。当前实现把模型提炼内容保留为“模型推断”，必须由用户确认；只有绑定到具体结果证据后，才允许升级为已验证来源。

### 4.3 整轮提炼

本轮结束时复用现有轻量审核器，不新增每条输入一次的模型调用。审核输入增加：

- 失败工具列表；
- 已恢复工具列表；
- 本轮用户文本与最终回答；
- 成功工具列表。

只有具备恢复证据时，才允许输出 `kind = experience` 的失败修复经验。经验应浓缩可复用的事实：适用条件、原因、修复和验证方式；不能照抄日志，不能编造原因。

普通偏好、项目决定仍按原流程提炼。

### 4.4 自动分流

沿用统一规则：

- 有明确、可核验来源、无未解决冲突、非全局、置信度达到门槛：自动生效；
- 模型仅凭工具名称提炼的内容仍是模型推断，进入待确认；
- 有冲突、全局升级或没有可核验来源：进入待确认；
- 自动生效保留撤销回执；自动采纳遇到同声明的有效旧记忆时停止，不自动替换，避免撤销无法恢复旧状态。

已验证来源的候选置信度为 0.80；未验证推断为 0.68，默认门槛为 0.70。

### 4.5 可观察性

继续使用现有事件和页面：

- 候选创建、自动生效、人工接受/拒绝；
- 检索候选与实际入模分开统计；
- 夜间报告展示可沉淀经验、冲突和语言问题。

失败经验上线初期重点观察：恢复工具数、形成经验数、自动采纳数、撤销数。没有结果验证时不计入“经验证采用”。

## 5. 数据与接口变化

不改变 SQLite 表结构。

- `RuntimeState` 增加有序的工具结果列表，每次新用户输入时清空；
- `SettledTurn` 增加 `failedToolNames` 与 `recoveredToolNames`；
- `turnFromState` 统一计算恢复证据；
- 审核提示词接收失败与恢复信息；
- 复用现有候选、来源、修订、撤销和检索机制。

## 6. 安全与隐私

- 不把工具原始错误正文发送给审核模型，只发送工具名称和本轮文本；
- 继续使用现有敏感信息过滤与“源码/日志正文不写记忆”限制；
- 记忆内容始终是历史证据，不因为被保存就获得新的执行权限；
- 全局范围和冲突内容仍需人工判断。

## 7. 测试与验收

至少覆盖：

1. 同一工具失败后成功，识别为已恢复；
2. 只有失败、先成功后失败、不同工具的成功，都不算恢复；
3. 新用户输入会清空上一轮工具结果；
4. 有恢复证据时审核器收到失败/恢复信息；
5. 已验证候选置信度能通过默认自动采纳门槛；
6. 无验证来源的推断仍需人工审核；
7. 现有记忆读写、检索、撤销和页面测试不回归；
8. 失败后再次失败会撤销恢复状态；记忆工具不会给新记忆提供证据；
9. 自动采纳不会替代冲突旧记忆；迟到的审核不能写入新轮次；
10. 中文凭证会被拦截，忙时审核排队而不是静默丢弃。

新会话中的真实验收：

- 构造一次“命令失败 → 修正 → 同命令成功”；
- 确认产生一条中文经验并自动生效；
- 构造一次“命令失败但未修好”，确认不产生成功经验；
- 页面能看到来源、变化与后续实际入模记录。

## 8. 后续迭代

1. 在输入时并行运行轻量预判，但仍只在整轮结束后写库；
2. 为失败经验保存结构化的“症状 / 根因 / 修复 / 验证 / 反例”，而不是压缩成一句话；
3. 把“结果被确认的采用”接入真实任务验收；
4. 用一组固定任务比较开启与关闭记忆的重复纠正、成功率和耗时。
